# HH-bot

Кроссплатформенный (Windows/Linux) ИИ-агент для помощи в поиске работы на [hh.ru](https://hh.ru).

## Возможности

1. Просмотр и управление профилем пользователя
2. Встроенный ИИ-агент
3. Анализ hh.ru по вакансиям: поиск, составление списка, подготовка резюме
4. Создание откликов и сопроводительных писем
5. Режимы работы:
   - **Подтверждение** — пользователь подтверждает действия агента
   - **Полное доверие** — агент всё делает сам (письма, отклики) без участия пользователя
6. Агент работает, пока включена программа
7. Постоянные системные уведомления с возможностью настройки внутри программы
8. Полноценный графический интерфейс

## ИИ-агент для поиска

Используется OpenAI-совместимый API (приоритет — Responses API). Пользователь сам добавляет URL и ключ; программа находит модели у провайдера, либо провайдер указывается явно. Настраиваются лимиты (запросов в минуту и т.д.).

У агента есть инструменты (поиск в сети, просмотр страниц и т.д.) — он полноценно ищет вакансии, создаёт резюме и ведёт диалоги с работодателями.

## Как это работает

При первом запуске пользователь:

1. Подключает ИИ (URL и ключ)
2. Вводит информацию о себе (для контекста ИИ)
3. Подключает профиль hh.ru
4. Настраивает программу

Далее пользователь задаёт (и может менять) теги вакансий, желаемый формат работы (на месте, удалённо, гибрид), пожелания по зарплате и т.д.

После настройки агент проходит по hh.ru, отбирает вакансии, готовит резюме под навыки (для максимального совпадения) и формирует полноценное резюме для hh.ru. Если пользователь одобрил базовое резюме — агент загружает его и начинает рассылать отклики с сопроводительными письмами: автоматически или по подтверждениям, в зависимости от настроек.

## Сборка и запуск на Linux

Требования: Rust (https://rustup.rs), Node не обязателен (фронтенд статический).

1. Системные зависимости (Debian/Ubuntu):
   ```
   sudo apt install build-essential libwebkit2gtk-4.1-dev libxdo-dev \
     libayatana-appindicator3-dev librsvg2-dev patchelf
   ```
2. Сборка и запуск в режиме разработки:
   ```
   cd HH-bot/src-tauri
   cargo run
   ```
3. Сборка пакета (.deb):
   ```
   cargo tauri build   # или: cargo build --release
   ```

### Первый запуск

1. Запустите приложение — откроется экран входа. Нажмите «Войти через hh.ru»,
   войдите на сайте, затем вставьте в приложение код подтверждения (или всю
   ссылку, которую покажет hh.ru). Регистрация приложения на dev.hh.ru не нужна.
2. После входа открывается вкладка «Профиль» — данные аккаунта и список резюме.
3. Вкладка «Настройки» — ИИ-провайдеры: можно добавить несколько
   OpenAI-совместимых API (название, base URL, ключ, модель), проверить
   подключение и выбрать активный.

### Todo-планы агента

Для сложной задачи агент составляет план через `create_todo_plan`: разбивает работу
на шаги, отмечает текущий шаг и ставит галочки только после выполнения. План доступен
во всех режимах, включая «Чат», без отдельных подтверждений. Простые вопросы агент
решает без плана.

Карточка над полем сообщения показывает прогресс, выполненные шаги, блокировки с
причинами и отменённые действия. План можно свернуть, скопировать в Markdown или
выбрать предыдущий из истории. Кнопка «Продолжить» отправляет агенту просьбу прочитать
актуальное состояние плана и выполнить оставшиеся шаги. Остановка и ошибки не
превращают незавершённые шаги в выполненные.

`read_todo_plans` возвращает планы только текущего чата. `update_todo_plan` меняет
заголовок, порядок, состав шагов, статусы и заметки, архивирует и возвращает планы из
архива. Обновление передаёт весь список с постоянными ID и текущую `revision`; при
конфликте версии агент перечитывает данные. Одновременно допускается один шаг в
работе и один незавершённый план. Лимиты: 60 шагов в плане и 100 планов в чате.

Обновления плана имеют отдельный лимит 120 вызовов за запуск и не расходуют лимит
40 рабочих действий.

Планы сохраняются в `todos.json` в каталоге данных приложения, независимо от истории
ответов. Запись атомарная, изменения из разных чатов защищены общей блокировкой.
Удаление чата или очистка истории удаляет его планы. При следующем сообщении агент
получает сохранённое состояние, даже если старые сообщения уже вышли из контекста.
В `?demo` доступны живой прогресс, ожидание вопросов, остановка и восстановление
планов после перезагрузки страницы без обращений к аккаунту hh.ru.

### Резюме и уточняющие вопросы

Кнопка «Создать резюме» в профиле начинает новую задачу агента. Если выбран режим
«Чат», для этой работы включается «Подтверждение». Агент использует знания о
пользователе и спрашивает недостающие сведения через форму внизу чата. Форма
поддерживает варианты, собственный ответ и многострочный текст; введённые ответы
сохраняются при переключении между задачами. «Отменить вопросы» возвращает отмену
агенту, а кнопка остановки завершает задачу. Формы доступны для любых тем, не только
для резюме. Ответы сохраняются в деталях соответствующего шага «Уточняет детали» в «Ходе работы» и учитываются в следующих сообщениях. Отдельного блока под сообщением или в финальном ответе нет.

Инструменты `create_resume` и `update_resume` используют мобильный API hh.ru: `POST /resume_profile` создаёт черновик, `GET /resume_profile/{id}` возвращает шаги и требования, `PUT /resume_profile/{id}` сохраняет шаг с `current_screen_id`. Запросы передают Android User-Agent и `X-HH-App-Active`.
Новое резюме всегда создаётся со скрытой видимостью. `publish_resume` публикует его
и открывает зарегистрированным работодателям, `unpublish_resume` скрывает.
`resume_reference` помогает получить справочники и требования к полям.
Ошибки доступа и проверки полей возвращаются агенту; открытие ручной формы hh.ru
остаётся доступным отдельной кнопкой. Доступность операций зависит от прав
OAuth-приложения на стороне hh.ru.

Агент работает с той же базой заметок, что и вкладка «Знания». `list_knowledge`
ищет по тексту и теме, фильтрует по теме и возвращает страницы с `next_offset`;
`read_knowledge` читает запись по постоянному ID, `list_knowledge_topics` показывает
темы и число заметок. `read_profile` возвращает полный список без прежнего ограничения
в 100 записей. `create_knowledge` создаёт заметки с индивидуальными темами,
`update_knowledge` исправляет текст или тему, `delete_knowledge` удаляет выбранные
записи, `rename_knowledge_topic` переносит заметки между темами, `merge_knowledge`
объединяет записи с сохранением ID первой. `update_profile` остаётся совместимым
инструментом добавления фактов.

Чтение доступно во всех режимах; изменения — в «Подтверждении» и «Полном доверии».
В «Подтверждении» каждое изменение требует согласия. Старые заметки получают ID
при загрузке. Проверка всех ID перед удалением защищает от частичного удаления,
а блокировка, атомарная запись и проверка версии при сохранении из интерфейса —
от повреждения файла и перезаписи изменений другого чата устаревшими данными.

Для создания используется журнал операций `resume-requests` в каталоге данных
приложения: ID сохраняется сразу после создания черновика. Повтор с тем же `request_id` продолжает заполнение этого черновика, не создавая второе резюме. Если сервер не
ответил, нужно проверить список резюме перед новой попыткой. Тесты не создают и
не публикуют реальные резюме:

```sh
npm --prefix ui run build
cargo test --manifest-path src-tauri/Cargo.toml
```

Для проверки интерфейса без аккаунта запустите `npm --prefix ui run dev` и откройте
адрес с `?demo`: создание резюме покажет пример формы, действия с карточками
изменят только демонстрационные данные.

Уровни профессиональных навыков доступны агенту через
`resume_reference(kind=skill_levels)` и `set_resume_skill_levels`. Их также можно
передать в `update_resume` как `skill_levels: [{name, level}]`, где уровень —
`base`, `middle` или `advanced`. Уровни самооценки сохраняются отдельным запросом
редактора hh.ru через общую веб-сессию приложения и проверяются чтением
`skills_with_levels` из мобильного профиля. Они общие для навыков аккаунта;
языковые уровни и результаты тестов этим инструментом не задаются.
